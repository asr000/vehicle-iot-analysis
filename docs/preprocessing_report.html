清洗规则与处理结果

  1. 时间：所有 timestamp 均可解析。timeMili 缺失 121,651 条，保留原值；52,202 条可比较记录的钟面差均为 5 小时 30 分钟。未据此擅自指定地理时区。
  2. 重复：完全重复和“设备、时间、变量”重复均为 0，没有执行重复删除。
  3. 位置：90,355 条 POSITION 均可拆成三个数值，暂命名 position_1、position_2、position_3。经纬度顺序及第三项含义等待字段说明，不将候选解释写成已知事实。
  4. 数值：83,498 条非位置记录中有 29 条转换失败，全部属于 PIDNameNotAvailable。该变量共 35 条，全部退出数值宽表并单独保存；其余 83,463 条数值记录保留。异常文件之间存在重叠，不可相加计算删除数量。
  5. 时间窗口：同一设备独立处理，窗口为 [起点, 起点+10秒)，每个字段取窗口内最后一个非空值，删除全部测量字段为空的窗口；不跨设备、不跨窗口传递数值。
  6. 缺失：无观测保留为空，不补零、不做无限前向填充或插值。missing_mask.csv 中 1 表示缺失、0 表示有观测。未报告的时间段不生成人造完整轨迹。
  7. 数值核查：提供分设备分变量的范围、分位数、负值和常量统计。对适用的连续数值使用 1.5 IQR 标记待核查候选，全部保留原值；统计极端值不等于传感器错误，未按未经确认的单位阈值裁剪。

复现与验收

推荐 Python 3.11，实际验证版本为 3.11.16。终端已进入 course 环境时：

python -m pip install -r requirements.txt
python run_pipeline.py
python build_delivery.py

run_pipeline.py 顺序执行预处理、对齐、正式数据、质量报告和验收；每个处理阶段只输出一行摘要。inspect_data.py 是单独的只读检查脚本，不由流水线自动执行。

  1. 确认 clean_wide.csv 的设备和时间键唯一、窗口起点对齐至 10 秒。
  2. 随机选择宽表非空单元格，在 feature_lineage.csv 找到同设备同窗口同字段记录，再按 source_row_id 定位原始 CSV 数据行；原文件含表头时物理行号为 source_row_id+1。
  3. 确认来源时间在窗口内，值等于该窗口最后一个有效原始观测；空单元格对应缺失标记 1。
  4. 检查告警各编码记录数合计与原始各编码数量一致，歧义窗口的单一标签为空。
  5. 查看 validation_results.json 中的实际检查项和结果；用交付清单核对文件大小与 SHA256。

GitHub 保存代码、文档和依赖；原始及逐条测量数据不纳入 Git 跟踪，完整输入与生成结果随离线交付包提供。
